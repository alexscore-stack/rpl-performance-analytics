# 🏟️ RPL Performance Analytics — Аналитическая витрина матчей РПЛ

ETL-пайплайн, объединяющий данные из двух независимых источников (football-data.co.uk и Understat) в единую аналитическую витрину для сравнения реальных голов с ожидаемыми (xG).

**Целевая аудитория проекта:** аналитический отдел футбольного клуба (оценка эффективности атаки, реализация моментов, тренды по сезонам).

## ⚙️ Архитектура ETL-пайплайна

### Extract
Загрузка данных из двух разнородных источников:
- CSV с football-data.co.uk → `data/rpl_raw.csv`
- Датасет Understat с Kaggle через `kagglehub` → распаковка в локальный кэш

### Transform

**1. Entity Resolution (сопоставление сущностей)**
Разные источники используют разные названия клубов. Реализован словарь `team_mapping` (21 правило), применяемый **к обоим источникам**:
```python
team_mapping = {
    'Dinamo Moscow': 'Dynamo Moscow',
    'FC Krasnodar': 'Krasnodar',
    'Torpedo Moscow': 'T. Moscow',
    # ... всего 21 правило
}
```

**2. Unpivot (переход к длинному формату)**
football-data хранит данные в широком формате (1 строка = 1 матч с Home/Away), Understat — в длинном (1 строка = 1 команда в матче). `df1` приведён к длинному формату через `pd.concat` двух датафреймов (home/away).

**3. Dimensional Modeling (справочник сезонов)**
Вместо жёсткой фильтрации по датам реализован справочник официальных дат начала и окончания каждого сезона РПЛ. Это автоматически исключает стыковые матчи (июнь) и предсезонные игры без риска обрезать июльские туры старта чемпионата.

**4. Unification (унификация форматов)**
- Даты → единый формат `datetime64[ns]`
- Сезоны → формат `YYYY/YYYY` (football-data) унифицирован с Understat
- Результаты → стандартизация `W/D/L`

### Load
Сохранение витрины в два формата:
- **CSV** — для быстрого доступа и Excel
- **SQLite** — демонстрация навыков работы с реляционными СУБД

## 🔍 Ключевые инженерные находки

### Проблема дублирования названий внутри источника
При анализе football-data обнаружилось, что одна команда может быть записана как `T. Moscow` и как `Torpedo Moscow` в разных сезонах. Решение: применить маппинг **к обоим источникам**, а не только к Understat. Это устранило ~30 "потерянных" матчей.

### Контроль качества через `indicator=True`
На этапе слияния использовался `pd.merge(..., how='outer', indicator=True)` для выявления расхождений между источниками. Изначально было ~1900 несовпадений — после применения справочника сезонов и полного маппинга достигнуто **100% совпадение (4774/4774)**.

### Расхождение в типах данных
При переносе кода из ноутбука в скрипт обнаружилось, что сравнение `datetime.date` и `datetime64[ns]` приводит к нулевому совпадению при merge. Решение: использовать нативный pandas `datetime64[ns]` во всём пайплайне.

## 🚀 Как запустить

```bash
# 1. Установить зависимости
pip3 install pandas kagglehub

# 2. Запустить Extract
python3 src/extract.py

# 3. Запустить Transform + Load
python3 src/transform+load.py
```

После выполнения в `data/rpl_final_vitrina.csv` и `database/rpl_analytics.db` будет доступна готовая витрина.
